# AIエージェント向け6業務ユースケース実証計画

この資料は、代表的な業務ユースケースを実データで検証するための計画です。アセスメントで成立条件を定めた後、同じ条件でAIエージェントの行動と業務成果を確認します。

## 1. 実証で確かめること

| 対象 | 確認すること |
|---|---|
| データ適合性 | 必要な情報を対象データから構成できるか |
| コンテキスト | 行動時点に必要な証拠と制約を供給できるか |
| エージェントの行動 | 定めた範囲で仕事を完了できるか |
| 業務成果 | 利用者が次の判断や作業へ進める結果になったか |

## 2. 代表シナリオ

| 業務成果 | エージェントに行わせる行動 | 検証するデータ | 人が判断する範囲 |
|---|---|---|---|
| 製品改善候補を企画会議へ提出する | 顧客の声、利用状況、リリース履歴を関連付け、候補と追加調査項目を作る | 顧客層、対象機能、製品版、時期、根拠 | 採用と優先順位 |
| 提案準備を短縮する | 顧客要件を事例、仕様、適用条件へ対応付け、提案骨子と確認質問を作る | 要件、導入事例、機能仕様、適用条件 | 価格と契約条件 |
| ナレッジの改訂候補を作る | 問い合わせ傾向と既存記事を比較し、重複、陳腐化、不足を整理する | 問い合わせ、解決記録、製品版、承認状態 | 記事の公開 |
| 設計変更のレビュー範囲を準備する | 変更対象から関連部品、図面、仕様、試験、過去変更をたどる | 部品ID、図面版、仕様、変更履歴、試験結果 | 設計変更の承認 |
| 契約レビューの確認範囲を整理する | 契約版、条項参照、定義、例外、関連文書を関連付ける | 契約版、条項、定義、有効期間、当事者 | 法的判断 |
| 調査結果を意思決定へ渡す | 複数資料の主張、根拠、反証、時点を整理する | 主張、証拠、出典、発行主体、調査方法 | 意思決定 |

## 3. 実証の進め方

1. アセスメント結果から、代表シナリオと成立条件を選びます。
2. 入力データ、基準時点、利用権限を固定します。
3. 期待する行動結果と必要な証拠を人手で定義します。
4. GraphRAGからAIエージェントへ渡したコンテキストを記録します。
5. エージェントの行動、停止、確認、最終結果を記録します。
6. 期待結果と実行結果を比較し、差分の発生段階を特定します。
7. 条件を変えた再実行で、結果の再現性を確認します。

## 4. 記録形式

| 記録対象 | 記録する内容 |
|---|---|
| 実証条件 | ユースケース、対象範囲、基準時点、権限 |
| 入力 | 使用したデータ、版、件数、前処理 |
| コンテキスト | 採用した証拠、原情報への参照、制約 |
| エージェントの行動 | 計画、判断、ツール利用、停止・確認 |
| 結果 | 生成物、完了状態、人による修正 |
| 測定値 | 品質、費用、応答時間、再現性 |
| 課題 | 不足、歪み、誤った判断、運用上の条件 |

## 5. 判定

実証結果は、成立、条件付き成立、データ準備、ユースケース調整のいずれかで記録します。判定には、使用した証拠、成立条件、残課題、次の対応を添えます。

測定項目の定義は[段階別評価方式](../evaluation.md)、事前の判断方法は[ユースケース・データ適合アセスメント](../enterprise-data-assessment.md)に示します。
