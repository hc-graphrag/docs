# 6業務ユースケース実証計画

状態: 実験仮説。顧客データでの検証結果ではありません。コード雛形は https://github.com/hc-graphrag/rag-usecase-demos を参照。

| 業務 | 仮説質問 | 最小構造 | 提案成功条件 |
|---|---|---|---|
| 設備保全 | 同じ設備の警報、交換部品、復旧手順は何か | 設備、部品、作業票、時刻、出典 | 正しい設備・版の記録を引用。現在状態は台帳/API照会 |
| サポート | 似た症状と承認済み対応は何か | チケット、製品版、症状、解決 | 解決例と有効記事を区別し、危険手順は棄権 |
| 設計図面 | 部品の接続先、改訂、関連仕様は何か | 図面版、部品ID、注記、BOM、座標 | ページ・版・部品IDが検証可能 |
| Excel/CSV | 条件に合う値と計算根拠は何か | ファイル/シート/範囲、型、単位、行ID | 集計はコード/DBで行い、原文セルを引用 |
| 契約書 | 更新期限、解約条件、例外はどの条項か | 契約版、条項、当事者、日付 | 現行版と条項を提示し、法的判断は人へ |
| 診療記録 | 期間内の薬剤変更と記載根拠は何か | 仮名患者、時刻、薬剤、出典 | 合成データで先行。実診療・治療推奨には使わない |

## 段階

0. 合成デモで検索・出典のコード経路を確認。精度の実証にはしない。
1. 所有者承認済みの非機密サンプルで代表性と制約を調べる。
2. 固定質問で現行方式と複数検索をオフライン比較する。
3. シャドー運用で権限、更新、監査、遅延を観察する。
4. 業務責任者・安全/法務の承認、監視と撤回手順の後に限定導入する。

全実験でコーパス版、質問・正解根拠、モデル、チャンク方式、top-k、グラフ抽出設定、ACL、費用、遅延、評価者を記録します。demo設定は決定的な語彙検索のみで、LLM評価結果を含みません。
