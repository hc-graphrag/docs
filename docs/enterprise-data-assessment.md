# 企業データ構造化と導入アセスメント

状態: 提案。実データの調査前に質問票として使用します。

## 質問票

### 業務と検索
- 利用部門、判断責任者、検索する作業と段階
- 代表質問、難問、答えられない場合の扱い
- 現状の所要時間、誤検索や見落としの影響
- 検索、要約、比較、推奨のどこまで必要か

### データと権限
- ソース、形式、件数、容量、所有者、更新・削除頻度
- 文書ID、版管理、個人情報・機密・保持期間
- 文書単位または行・列単位のACLとID連携
- スキャンPDF、表、図面、手書きの割合
- 利用できるAPI、エクスポート、テスト環境

### 品質と運用
- OCR誤り、文字化け、欠損、重複、表記揺れ
- 用語集、型番、人名、設備IDの台帳
- 更新・削除の反映期限、監査ログ、出典要件
- 運用、承認、障害対応の担当者

## レコード案

| 項目 | 説明 |
|---|---|
| source_id, version_id | 安定したソースIDと版 |
| source_uri, page_or_sheet, span | 原文位置 |
| tenant_id, acl | 検索前に適用するアクセス属性 |
| created_at, updated_at, valid_from/to | 変更と有効期間 |
| content_type, language, parser_version | 形式と変換系統 |
| chunk_id, parent_id, text | チャンクと親文書 |
| entities, relations | 任意のグラフ要素と抽出根拠 |
| checksum, deleted_at | 差分検出と削除伝播 |

## 導入ゲート

1. 許可を得て代表的な小さなサンプルを取得できる。
2. 回答候補から原文ページ・表・行へ戻れる。
3. 検索前に権限を適用し、変更・削除も反映できる。
4. 現行手段の時間・品質と正解根拠がある。
5. 更新、再索引、監視、ログ、ロールバックの責任者がいる。

未達項目があれば検索調整より先に不足を解消します。診療記録などは合成データの技術確認と実データ利用審査を分けます。
