# GraphRAGテンプレートによる短期導入モデル

状態: あそぴてっくの提供方針。期間・精度・費用の実績値は案件ごとの検証前には確定しません。

## 1. 利用者へ提供する価値

利用者にとって、GraphRAG、ベクトル検索、キーワード検索のどれが優れているかは中心課題ではありません。必要なのは、業務上の問いに対して、短期間で、根拠を確認できる高品質な回答を得られることです。

あそぴてっくは方式選定と技術調整を引き受け、利用者が本来のビジネス課題へ集中できる状態を作ります。

- どの判断を改善するか
- どの業務を速く、正確にするか
- どの情報を整備・更新するか
- 回答をどの業務フローへ組み込むか
- 導入後の成果をどう測るか

## 2. GraphRAGを標準候補にする理由

GraphRAGは唯一の正解ではありません。あそぴてっくが標準候補として先に採用する理由は、実体・関係・主張、局所から全体までの複数解像度、来歴付きコンテキストを使う高度な回答基盤を、共通部品として組み立てやすいためです。

この共通化により、案件ごとに方式比較から始める範囲を減らし、利用者のデータ、質問、判断基準を使った検証へ早く進めます。

## 3. テンプレート化する範囲

| 層 | テンプレート |
|---|---|
| 取り込み | 文書ID、版、権限、更新、削除、原文位置 |
| 圧縮表現 | チャンク、実体、関係、主張、コミュニティ、要約 |
| 検索 | local、global、DRIFT、必要な補助検索 |
| 注入 | 証拠束、関係、要約、出所、制約の組み立て |
| 回答 | 根拠表示、棄権、形式、利用者別の出力 |
| 評価 | 代表質問、期待証拠、圧縮損失、回答品質、費用、遅延 |
| 運用 | 更新・削除伝播、監視、監査、再評価 |

テンプレートは業務データや判断基準を固定するものではありません。反復する技術基盤を固定し、案件固有のビジネス課題へ使える時間を増やします。

## 4. 導入の流れ

1. ビジネス課題、利用者、判断、成功条件を確認する。
2. 代表データと代表質問を小さく選ぶ。
3. GraphRAGテンプレートへデータを接続する。
4. 回答品質、根拠、費用、遅延を測る。
5. 技術者側で検索経路、解像度、モデル、補完方式を調整する。
6. 利用者と業務上の有用性を確認する。
7. 更新・権限・監視を含む運用へ広げる。

方式の説明や比較は、利用者の意思決定に必要な範囲で行います。利用者へ技術方式の選定作業を要求しません。

## 5. コストと品質の管理

コストと品質の比較は技術者側の責任です。

### コスト

- 初期接続とデータ整備に必要な期間
- 索引・グラフ構築の時間と費用
- 質問ごとの遅延と費用
- 更新、削除、権限変更の反映費用
- 監視、再評価、障害対応の運用費用

### 品質

- 必要な事実・関係・例外を取得できるか
- 原文、版、位置へ戻れるか
- 回答が証拠に支持されているか
- 情報不足時に適切に確認・棄権できるか
- 利用者が業務判断を完了できるか

GraphRAGだけで品質や費用を満たせない部分には、キーワード、ベクトル、構造化照会、ルール等を補助的に組み合わせます。利用者にとっては一つの回答基盤として提供します。

## 6. 短期間・高精度という表現

短期間で高精度な回答を得やすくすることは、このテンプレートの設計目標です。全案件で同じ期間・精度を保証する表現ではありません。

提案時には、対象範囲、代表質問、期待証拠、品質基準、測定期間を合意します。検証後は、達成した数値、失敗例、適用範囲、残存リスクを報告します。

## 7. 完了条件

技術デモが動くだけでは完了ではありません。利用者が方式名を意識せず、必要な回答と根拠を得て、本来の業務判断へ進める状態を完了条件とします。
